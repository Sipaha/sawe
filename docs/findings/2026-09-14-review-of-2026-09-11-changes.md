## Fails open (the permission work's own guarantees)

1. **`crates/solution_agent/src/store.rs:1750`** — `is_ephemeral_session` tests only
   `is_supervisor_ephemeral`, ignoring `is_ephemeral`. `generationOnly` sessions
   (commit-message generation) are therefore persisted **and** soft-closed, so they show
   up in "Reopen Closed Chat". Reopening rebuilds from `SolutionSessionMetadata`, which
   carries no `is_ephemeral`, so `build_session_meta` omits `generationOnly` and emits
   `sawePermissionMode:"full_access"` → the session respawns with
   `--tools default --permission-mode bypassPermissions --allow-dangerously-skip-permissions`,
   resuming a transcript created under a "no tools, ever" contract. Side effect: every
   generation run leaves a stray closed chat in the picker.
2. **`crates/solution_agent/src/store.rs:1173`** — the persisted default permission mode
   is loaded only after the DB connects. A chat created inside that window gets
   `FullAccess`, i.e. the remembered default fails **open**, not closed.
3. **`crates/codex_native/src/codex_native.rs:537`** — `disable_mcp_servers` builds the
   override key as `mcp_servers.{name}.enabled` without TOML-quoting `name`, while the
   sibling `plugins` loop three lines below does quote it
   (`serde_json::to_string(name)`). A server whose name contains a dot, space or quote
   gets an override under the wrong key and stays **enabled** in a read-only session.
4. **`docs/src/ai/codex.md:27`** — documents "workspace-write sandboxing and on-request
   approvals"; `codex_native.rs:518` actually sends
   `"approvalPolicy":"never"` + `"sandbox":"danger-full-access"` (read-only sessions get
   `"read-only"`). The doc describes a safer product than the code ships.

## Lost or mis-ordered messages

5. **`crates/solution_agent/src/store/acp_event.rs:383`** — a plain Stop clears
   `pending_messages` without consulting `active_steers`, so a follow-up Codex already
   accepted through steering never gets its transcript entry: the user sees the message
   vanish while the agent acts on it.
6. **`crates/claude_native/src/connection.rs:631`** — `read_only_prompt_allowed` rejects
   any message whose first non-space char is `/`, so `"/home/spk/proj/src/main.rs:42 —
   explain this"` is refused as an unknown slash command. If it arrived from the queue,
   `flush_stopped_queue` (`steering.rs:236`) already `drain(..)`-ed the bundle, so the
   text is gone, not re-queued.
7. **`crates/claude_native/src/connection.rs:742`** — read-only Claude sessions register
   an **empty** hook map, silently disabling the only mid-turn delivery path Claude has
   (`PostToolUse`/`Stop`/`SubagentStop` → `shared.pending_pull`). `try_steer_pending`
   only handles `CodexConnection`, so for Claude there is no steering fallback:
   follow-ups and — worse — cooperative compaction requests wait until the turn ends,
   possibly past the hard context limit. Nothing logs the degradation.
8. **`crates/solution_agent/src/store/queue.rs:323`** — `cancel_turn` revokes the peer
   wake before the in-flight check, so "Send now" disables peer messaging and can strand
   a peer-only queue.
9. **`crates/solution_agent/src/upload.rs:454`** — a queued chunk rejection is never
   cleared when a later chunk for the same upload succeeds, and the drainer emits all
   acks before all rejections. The client is told to rewind past bytes the server
   already acked: self-healing, but an extra round trip per glitch.

## Cherry-pick suggestions — a silent 100× budget regression

10. **`crates/solution_git/src/ai_cherry_pick_suggest.rs:407`** — `estimate_tokens`
    charges the prompt's **byte** length (+2048 envelope) against `token_budget`, whose
    default (`DEFAULT_TOKEN_BUDGET = 25_000`) and setting name are denominated in
    **tokens**. One typical pair now costs ~19 000 of 25 000; the second trips the
    budget. Before the change a pair cost a flat 250 — 100 pairs per run. Same setting,
    ~1 pair analyzed, `budget_exhausted = true`.
11. **`…/ai_cherry_pick_suggest.rs:393`** — a pair whose estimate alone exceeds the whole
    budget aborts the entire run (`return Ok(..)` at :297) instead of being skipped, so
    one large pair truncates every remaining cheap pair, deterministically, on every run.
12. **`…/ai_cherry_pick_suggest.rs:215`** — `list_head_paths(..)?` (and
    `list_commit_paths(..)?` at :560) replaced `.unwrap_or_default()`, so one member with
    a non-UTF-8 path or a >1 MiB tree listing now fails the whole cross-member analysis
    instead of degrading that one member.

## remote_control listener split

13. **`crates/remote_control/src/listener.rs:1687`** — `CLOSE_WRITE_TIMEOUT_SECS = 10`
    cannot cover what its own doc comment says it must. The close frame must first drain
    the remainder of the frame it preempted, whose budget scales to 30 s + 1 s/32 KiB
    (830 s for 25 MB). On a slow link the preemption delivers nothing and the peer still
    gets a bare TCP reset — exactly the case N-51/N-54 set out to fix. The guard test
    `close_grace_exceeds_the_close_write_budget` only asserts 25 > 10.
14. **`crates/remote_control/src/listener.rs:620`** — the 1-failure grace path returns
    before the `BAN_LIST_MAX_ENTRIES` eviction, so the cap is never enforced for
    single-failure subnets — and the new CGNAT full-/32 keying (:325) multiplies the
    distinct keys an attacker can mint by 256×. The map grows to ~108 000 records
    (~10× the documented cap) with an O(n) `retain` on every accept.

Also noted but not counted: `listener.rs:952` (`kick_existing_for_client` drops
`active_conns` before pushing the new slot, so the documented "never two slots per
client" invariant is not enforced) and `listener.rs:1435` (the teardown comment promises
queued responses still go out; the writer's `biased` select takes the close first and
drops them). Both are pre-existing structure this diff only documents.

## Patterns

Six defects out of fourteen are the same reflex in different clothes: **an unknown or
restricted state resolving to the permissive value.** A `generationOnly` session that lost
its flag became full-access; an unread preference became full-access; an unquoted server
name stayed enabled; read-only inherited generation-only's hook suppression by grouping
rather than by reasoning; the docs described the safe configuration rather than the shipped
one. The mechanisms in this change set are strong — the DB migration, the steering
receipts, the reader/writer split and the notification channel all survived adversarial
review — but the EDGES of the permission model were consistently resolved in the
permissive direction.

Two more are arithmetic that stopped matching its inputs: a token budget charged in bytes,
and a default sized for a prompt 20× smaller than the one now sent. Both were invisible
because the failure is silent (a "budget exhausted" label, not an error).

The last group is guard tests that assert the weaker claim — `25 > 10` instead of "the
budget covers the frame it must flush", and a capacity cap never exercised on the one
population that can actually grow. A test that pins a constant is not a test that pins the
property the constant exists for.
